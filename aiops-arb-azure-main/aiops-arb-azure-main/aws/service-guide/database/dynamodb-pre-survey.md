## 1. 테이블 목록

사용 중인 DynamoDB 테이블을 모두 기재해 주세요.

> **설계 방식 안내**
> - **Single Table Design**: 여러 종류의 데이터(엔티티)를 하나의 테이블에 함께 저장하는 방식입니다. 예를 들어 주문, 상품, 배송 정보를 하나의 테이블에 저장합니다. 엔티티 간 관계 조회가 많거나 트랜잭션 처리가 필요한 경우 적합합니다.
> - **Multi Table Design**: 엔티티 종류별로 테이블을 분리하여 저장하는 방식입니다. 예를 들어 주문 테이블, 상품 테이블, 배송 테이블을 각각 따로 만듭니다. 엔티티가 독립적이고 조회 패턴이 단순한 경우 적합하며, 엔티티별로 PITR(Point-in-Time Recovery) 또는 Export를 독립적으로 수행해야 하는 경우에도 적합합니다.

| AP-05 | Read | 특정 사용자의 특정 기간 주문 조회 | uid = `{userId}`, cat between `2026-05-01T00:00:00Z` and `2026-05-31T23:59:59Z` | amt > `10000` | gsi_user_orders |
