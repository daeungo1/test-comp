1. 개요

ARB 팀이 서비스 AWS 계정의 리소스 상태를 점검할 수 있도록 IAM Role을 포함한 읽기 전용 리소스를 생성합니다.

항목내용
권한 범위AWS 관리형 정책 ReadOnlyAccess (쓰기/삭제 권한 없음)
사용 주체ARB 팀 계정(260544022684)의 특정 Role만 Assume 가능
배포 방식CloudFormation 웹 콘솔에서 스택 업로드 (AWS CLI 불필요)
예상 소요 시간10분 내외 (리저널 스택을 배포하는 리전당 3 ~ 5분 추가)
점검 완료 후생성한 스택을 삭제하면 생성된 리소스와 권한도 함께 정리됨

  2. STEP 2. 리저널 스택 배포 (대상 리소스가 있는 리전마다) → 리전별 리소스 접근 설정

2. 준비물

  • CloudFormation 템플릿 파일 2개 (아래 버튼으로 다운로드)
  • 서비스 AWS 계정의 관리자(또는 유사 권한) 수준의 콘솔 접근 권한
  • 서비스가 사용하는 리전 목록

3. STEP 1. 글로벌 스택 배포 us-east-1에서 1회

1

AWS 콘솔에서 CloudFormation 열기

  1. 서비스 AWS 계정에 로그인합니다.
  2. 콘솔 우측 상단의 리전 선택기를 US East (N. Virginia) · us-east-1로 변경합니다.
    💡 배포 리전 안내 IAM은 글로벌 리소스라서 어느 리전에서 배포해도 동일하게 동작합니다.
    다만 이 가이드에서는 관리 편의를 위해 us-east-1을 기준 리전으로 안내하고 있습니다.
    익숙한 다른 리전에서 배포하셔도 무방합니다.
  3. 서비스 검색창에 CloudFormation을 입력해 이동합니다.
2

스택 생성

  1. 좌측 메뉴에서 Stacks → 우측 상단 Create stack → With new resources (standard) 클릭.
  2. Prepare template: Choose an existing template 선택.
  3. Template source: Upload a template file 선택 후 01-global.yaml을 업로드.
  4. Next 클릭.
3

스택 이름 입력

  1. Stack name: arb-readonly-global (권장)
  2. 파라미터 입력 항목은 없습니다. Next 클릭.
4

스택 옵션 및 리뷰

  1. Configure stack options 페이지는 대부분 기본값 그대로 두되, 하단의 Capabilities 섹션에서 체크박스를 선택합니다. 
    ☑ I acknowledge that AWS CloudFormation might create IAM resources with custom names.
    이 템플릿은 IAM Role을 ARB-ReadOnly-Role이라는 고정 이름으로 생성하므로 위 항목 체크가 필요합니다.
    체크하지 않으면 다음 단계로 넘어갈 수 없습니다.
  2. Next 클릭.
  3. Review 페이지에서 입력 내용을 확인한 후 Submit 클릭.
5

배포 완료 확인

  • Status가 CREATE_COMPLETE가 되면 성공입니다 (1 ~ 2분 소요).
  • 만약 CREATE_FAILED가 나온다면 FAQ를 참고하세요.

4. STEP 2. 리저널 스택 배포 대상 리소스가 있는 리전마다 반복

이 스택은 아래 대상 리소스 중 하나라도 있는 리전에서 배포합니다.
서비스가 여러 리전을 사용한다면 각 리전마다 이 스텝을 반복합니다.

💡 시작 전에 Role ARN 준비

이 스택의 파라미터로 STEP 1에서 생성한 IAM Role의 ARN이 필요합니다.
아직 확인하지 않았다면, us-east-1 CloudFormation의 arb-readonly-global 스택 → Outputs 탭 → RoleArn 값을 복사해 두세요.

(STEP 3에서도 동일한 값을 사용합니다)

대상 리소스

리저널 스택은 아래 리소스 타입에 대한 ARB 읽기 접근을 설정합니다.

리소스 타입해당 파라미터설명
EKS 클러스터 EksClusterName1 ~ EksClusterName5 클러스터당 Access Entry 생성 (ViewOnly)

사용하는 리소스에 해당하는 파라미터만 채우고 나머지는 비워둡니다.
해당 리전에 대상 리소스가 하나도 없다면 이 스택은 배포하지 않아도 됩니다.
(향후 확장을 고려해 빈 값으로 배포해두셔도 무방합니다.)

1

대상 리전으로 이동

  1. 콘솔 우측 상단 리전 선택기를 배포할 리전으로 변경합니다. 예: Asia Pacific (Seoul) · ap-northeast-2
  2. CloudFormation 서비스로 이동합니다.
2

스택 생성 및 템플릿 업로드

  1. Create stack → With new resources (standard).
  2. Upload a template file로 02-regional.yaml을 업로드하고 Next 클릭.
3

파라미터 입력

  1. Stack name: arb-readonly-regional (권장)
  2. Required 섹션 입력:
    파라미터값
    ARB Role ARN STEP 1에서 생성한 arb-readonly-global 스택의 Outputs 탭에서 RoleArn 값을 복사해 붙여넣기
    arn:aws:iam::<계정 ID>:role/ARB-ReadOnly-Role
  3. EKS Clusters in this region (optional, up to 5) 섹션 입력:
    • 해당 리전에 있는 EKS 클러스터 이름을 EKS cluster name #1부터 채워 넣습니다.
    • 클러스터 개수만큼만 채우고 나머지는 빈 칸으로 두세요.
    💡 EKS 클러스터 이름 확인 방법 콘솔 → Elastic Kubernetes Service → Clusters에서 확인하거나,
    CLI에서 aws eks list-clusters --region <리전>으로 조회할 수 있습니다.
  4. Next 클릭.
4

스택 옵션 및 리뷰

  1. Configure stack options 페이지는 기본값 그대로 두고 Next 클릭.
    이 스택은 IAM Role을 생성하지 않으므로 Capabilities 체크박스는 나타나지 않습니다.
  2. Review 페이지에서 입력 내용을 확인한 후 Submit 클릭.
5

다른 리전도 동일 절차로 반복

대상 리소스가 있는 각 리전에서 위 1 ~ 4단계를 반복합니다.

✅ STEP 2 완료 조건 대상 리소스가 있는 모든 리전에서 arb-readonly-regional 스택이 CREATE_COMPLETE 상태가 되면 완료입니다.

5. STEP 3. Role ARN을 ARB 팀에 전달

모든 스택 배포가 완료되면 ARB 팀에 Role ARN을 공유합니다.

1

Role ARN 복사

  1. 리전을 us-east-1로 변경합니다.
  2. CloudFormation → arb-readonly-global 스택을 클릭합니다.
  3. 상단 탭 중 Outputs 탭으로 이동합니다.
  4. Key가 RoleArn인 행의 Value를 복사합니다. 
    arn:aws:iam::<서비스 계정 ID>:role/ARB-ReadOnly-Role
2

ARB 팀에 전달

✅ 전달 내용 위에서 복사한 Role ARN을 ARB 팀 담당자에게 전달합니다.

전달이 완료되면 사전 준비 단계가 모두 끝난 것입니다.
ARB 팀의 점검 수행을 기다린 후, 점검 완료 통보를 받으면 STEP 4로 진행합니다.

6. STEP 4. 점검 완료 후 정리

ARB 팀으로부터 점검 완료 통보를 받으면 생성한 스택을 삭제합니다.
삭제 순서가 중요합니다.

⚠️ 삭제 순서

반드시 리저널 스택을 먼저 모두 삭제한 후에 글로벌 스택을 삭제하세요.

순서를 지키지 않으면 IAM Role이 먼저 지워지면서 리저널 리소스에 연결된 Principal ARN이 orphan 상태가 될 수 있습니다.

1

리저널 스택 삭제 (배포했던 모든 리전에서)

  1. 각 리전의 CloudFormation 콘솔로 이동합니다.
  2. arb-readonly-regional 스택을 선택한 후 Delete 클릭.
  3. Status가 DELETE_COMPLETE가 되면 다음 리전으로 이동합니다.
2

글로벌 스택 삭제 (us-east-1)

  1. 리전을 us-east-1로 변경합니다.
  2. arb-readonly-global 스택을 선택한 후 Delete 클릭.
  3. Status가 DELETE_COMPLETE가 되면 정리 완료입니다.
3

(해당 시에만) 자동 생성된 S3 버킷 삭제

  1. STEP 1, 2를 배포한 각 리전의 S3 콘솔에서 cf-templates-으로 시작하는 버킷을 찾습니다.
  2. 버킷의 생성 시점이 STEP 1 / STEP 2를 배포했던 시점인지 확인합니다.
  3. 생성 시점이 배포 시점이라면 이번 배포 시 자동 생성된 버킷이므로 Empty로 비운 뒤 Delete합니다.
  4. 생성 시점이 그보다 이전이라면 기존부터 존재하던 버킷이므로 그대로 둡니다.

더 자세한 내용은 FAQ를 참고하세요.

✅ 정리 완료 모든 스택이 삭제되면 ARB 팀은 더 이상 서비스 계정에 접근할 수 없습니다.

7. FAQ / 문제 해결

Q1. Role 이름을 변경해도 되나요?

아니요. ARB 팀 자동화 도구가 ARB-ReadOnly-Role이라는 이름을 기준으로 동작합니다.
리저널 스택의 RoleArn 파라미터에도 이 이름이 포함되어 있어야 유효성 검사를 통과합니다.

Q2. STEP 1에서 CREATE_FAILED가 발생합니다.

같은 이름의 Role(ARB-ReadOnly-Role)이 이미 계정에 존재할 가능성이 높습니다.
IAM 콘솔에서 중복 Role을 확인한 후, 동일한 목적의 리소스라면 기존 스택을 찾아 재사용하거나, 충돌하는 Role을 삭제한 뒤 재시도하세요.
Role 생성 권한이 부족한 경우라면 계정 관리자에게 문의해 주세요.

Q3. STEP 2에서 EKS 클러스터 이름을 잘못 입력했어요.

존재하지 않는 클러스터 이름을 입력하면 Access Entry 생성이 실패합니다.
스택을 삭제한 후 올바른 이름으로 다시 배포하거나, Update stack으로 파라미터를 수정하세요.

Q4. 리전 하나를 추가로 배포해야 합니다. 처음부터 다시 해야 하나요?

아니요.
추가할 리전의 CloudFormation 콘솔에서 02-regional.yaml만 새로 배포하면 됩니다.
글로벌 스택은 그대로 유지됩니다.

Q5. 점검 도중에 추가 리소스를 더 만들었는데, 다시 배포해야 하나요?

IAM Role은 ReadOnlyAccess 관리형 정책을 사용하므로 이후 새로 생성된 리소스도 자동으로 조회 가능합니다.
다만 새로운 EKS 클러스터가 생긴 경우에는 해당 리전의 리저널 스택에서 Update stack으로 클러스터 이름을 추가해 주세요.

Q6. Role이 너무 강한 권한을 가지는 건 아닌가요?

ReadOnlyAccess는 AWS가 관리하는 정책으로, 모든 서비스에 대한 조회(Get/List/Describe) 권한만 포함합니다.
쓰기/수정/삭제는 불가능합니다.
또한 Trust Policy에 의해 ARB 계정의 특정 Role만 Assume할 수 있으므로 외부 접근은 차단됩니다.

Q7. cf-templates-* 버킷은 무엇인가요?

최초 1회 CloudFormation 템플릿 파일을 Upload a template file로 올리면
AWS가 리전마다 cf-templates-* 버킷을 자동으로 생성하고 그 안에 템플릿 파일을 보관합니다.
(해당 리전에 이미 cf-templates-* 버킷이 존재하면 해당 버킷을 그대로 사용합니다.)

이 버킷은 스택의 리소스가 아니라 CloudFormation이 자체적으로 관리하는 것이므로, 스택을 삭제해도 함께 삭제되지 않습니다.
자동 생성된 버킷이므로 사내 S3 보안 정책이 적용되어 있지 않으며, 보안 점검 시 탐지될 수 있습니다.
이번 배포만을 위해 새롭게 생성되었다면 삭제를 권장합니다.

문의: ARB 팀 담당자
이 문서는 ARB 점검 프로세스와 함께 제공되며, 점검 종료 후에는 스택 삭제와 함께 보관 의무가 없습니다.
