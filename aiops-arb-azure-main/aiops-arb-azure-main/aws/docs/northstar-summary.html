🌟 NorthStar T/F 현황 요약

작성일: 2026-08-10  |  출처: aiops-northstar 레포 분석  |  Cloud Operation Group

💡 NorthStar는 그룹 내 여러 과제가 AI Agent를 쉽게 도입할 수 있도록
공통 플랫폼(인프라 + 템플릿)을 만들어 보급하는 T/F입니다.

⚖️ ARB(KIRO 방식) vs 하네스(NorthStar 방식) 차이

구분 ARB (aiops-arb-kiro) 하네스 (NorthStar)
실행 환경 EC2에서 kiro-cli 프로세스 직접 실행 AWS ECS Fargate 컨테이너 + Bedrock AgentCore
Agent 정의 .kiro/agents/*.json + 프롬프트 파일 AGENTS.md + 스킬(skills) 폴더
인프라 구성 수동 EC2 설치, systemd 서비스 등록 Terraform 코드로 자동 배포
스킬 배포 로컬 파일 수정 후 서비스 재시작 S3 업로드 → EFS 마운트로 Agent 자동 인식
Slack 연동 Python 스크립트 (slack_bot.py) ECS Fargate 컨테이너 (slack-gateway) 분리 운영
보안 EC2 IAM Role IAM Role + Bedrock Guardrail (답변 필터링) + 관측 로그
관리 복잡도 단순 — 한 서버에 모든 것 복잡하지만 확장 가능 — 과제별 독립 환경
💡 한 줄 비유: ARB는 "한 서버에 직접 설치한 방식", 하네스는 "클라우드 네이티브 컨테이너 방식"

🔧 하네스(Harness)가 뭔지 쉽게 설명

과제팀이 AI Agent를 쓰고 싶을 때 인프라를 처음부터 만들지 않아도 되도록, NorthStar가 미리 만들어둔 표준 틀입니다.

🔌 Slack Gateway

Slack 메시지를 받아서 AI에 전달하는 중계 서버.
각 과제별로 독립된 컨테이너로 운영됩니다.

🤖 Harness (Agent 실행 환경)

Agent들이 실제로 실행되는 컨테이너 환경.
Bedrock AgentCore 위에서 동작합니다.

🛠️ Skills (도구 모음)

Agent가 사용할 수 있는 기능 모음.
S3에 업로드해두면 Agent가 자동으로 읽어서 사용합니다.

🛡️ Bedrock Guardrail

AI 답변에서 욕설·민감정보가 나오지 않도록
AWS가 강제로 필터링하는 보안 레이어입니다.

🏗️ 전체 구조 (간략)

레이어구성 요소역할
중앙 계정 ECR, S3(스킬 원본), S3(Bedrock 로그) 스킬 원본 관리, 모델 호출 로그 수집
배포 계정 (과제별) VPC, ECS Fargate, DynamoDB, EFS, SSM 각 과제의 Slack Gateway + Harness 실행 환경
대상 계정 (N개) IAM Role (AIOps-Readonly) Agent가 AWS 리소스를 읽기 전용으로 조회
🔑 Slack → (WebSocket) → Gateway → AgentCore Harness → Bedrock 모델 → 대상 AWS 계정 (1-hop AssumeRole)

🔗 ARB와 NorthStar의 관계

⚠️ ARB는 현재 KIRO CLI 방식으로 NorthStar 하네스와 다른 방식으로 동작합니다.
NorthStar 목표 중 하나가 ARB 같은 과제들도 하네스로 전환하는 것이나,
현재는 SCP(서비스 제어 정책) 계정 권한 제약으로 AgentCore 연동이 보류된 상태입니다.

구분ARB 현재하네스 전환 시 변경점
Agent 실행 kiro-cli subprocess Bedrock AgentCore (ECS Fargate)
Agent 정의 .kiro/agents/*.json AGENTS.md + skills 폴더
인프라 관리 수동 (EC2, systemd) Terraform 자동화
Slack Bot Python slack_bot.py slack-gateway 컨테이너
